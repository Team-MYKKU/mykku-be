[[fcm-token-register]]
=== FCM 토큰 등록

로그인한 회원의 기기(`deviceId`)에 FCM 토큰을 등록하거나 갱신합니다(upsert).

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* *갱신*: 같은 회원이 같은 `deviceId` 로 다시 호출하면 새로 만들지 않고 `token` 값만 교체합니다. `id`, `createdAt`, `deviceType` 은 바뀌지 않으며 응답에도 기존 값이 담깁니다. 따라서 로그인 직후, 앱 시작 시, 토큰 갱신(onTokenRefresh) 시마다 같은 `deviceId` 로 호출하면 되고, 토큰이 바뀌어도 삭제 후 재등록할 필요는 없습니다.
* *deviceId*: 클라이언트가 만드는 값입니다. <<auth-logout,로그아웃>>의 `deviceId` 와 <<fcm-token-delete,FCM 토큰 삭제>>의 경로 파라미터에 같은 값을 써야 이 기기의 토큰이 삭제됩니다.
* *계정 전환*: 같은 `token` 이 다른 회원 계정에 등록되어 있으면 그 등록은 삭제됩니다. 한 기기에서 다른 계정으로 로그인해 같은 `token` 을 등록하면 이전 계정의 푸시는 더 이상 이 기기로 오지 않습니다.
* *token 중복 주의*: 하나의 `token` 은 하나의 `deviceId` 로만 등록하세요. 같은 `token` 이 여러 `deviceId` 로 등록되어 있으면 그 기기로 푸시가 중복 발송되고, 그 `token` 으로 등록을 요청하면 500 `C402` 가 반환됩니다. 이때는 <<fcm-token-list,목록 조회>>에서 쓰지 않는 `deviceId` 를 찾아 <<fcm-token-delete,삭제>>한 뒤 다시 등록하세요.
* 서버는 `token` 이 실제로 유효한 FCM 토큰인지 확인하지 않습니다.
* 신규 등록과 갱신 모두 200 OK를 반환합니다.
* *입력 검증*: `token` 또는 `deviceId` 가 빈 문자열이거나 공백이면 400 `C101` 이며, `message` 는 "FCM 토큰은 필수입니다" / "디바이스 ID는 필수입니다" 입니다(둘 다 해당하면 두 문구가 `+", "+` 로 연결됨). `token` · `deviceId` 필드가 없거나 `null` 이거나 JSON 형식이 잘못되면 `message` 는 "입력값이 올바르지 않습니다" 입니다(<<overview-common-errors,공통 에러>> 참고).
* *푸시 수신*: 알림이 생성되면 수신 회원이 등록한 모든 기기로 FCM 푸시가 발송됩니다. 메시지 형식(`notification.title` · `notification.body`, `data.type` · `data.relatedResourceId` · `data.relatedResourceType`)은 <<notification-push,푸시(FCM) 메시지 형식>>을 참고하세요.

[[fcm-token-list]]
=== FCM 토큰 목록 조회

로그인한 회원 계정에 FCM 토큰이 등록된 기기 목록을 조회합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 응답에는 토큰 문자열이 포함되지 않습니다. 현재 기기가 등록되어 있는지는 `deviceId` 로 확인하세요.
* 정렬 순서는 보장되지 않으며, 등록된 기기가 없으면 빈 배열(`[]`)을 반환합니다.

operation::fcm-token/list/200[snippets='http-request,request-headers,http-response,response-fields']

[[fcm-token-delete]]
=== FCM 토큰 삭제

로그인한 회원 계정에서 해당 `deviceId` 로 등록된 FCM 토큰을 삭제합니다. 삭제하면 이 계정의 알림 푸시가 이 기기로 발송되지 않습니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 해당 `deviceId` 로 등록된 토큰이 없어도(이미 삭제됐거나 다른 값인 경우) 404 없이 200 OK를 반환합니다(멱등).
* <<auth-logout,로그아웃>>이 같은 삭제를 수행하므로 로그아웃할 때는 따로 호출할 필요가 없습니다.

operation::fcm-token/delete/200[snippets='http-request,request-headers,path-parameters,http-response,response-fields']
