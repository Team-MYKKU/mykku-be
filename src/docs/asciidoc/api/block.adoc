[[block-member-create]]
=== 사용자 차단

다른 사용자를 차단합니다. 차단은 양방향으로 적용됩니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* `memberId` 에는 DB 숫자 ID가 아니라 회원 아이디 문자열을 보냅니다 (<<overview-identifier,식별자>> 참고).
* *적용 범위*: 로그인한 상태에서 <<board-feeds,보드별 피드 목록 조회>>와 <<board-popular-feeds,보드별 인기 피드 목록 조회>>를 호출하면, 내가 차단한 사용자와 나를 차단한 사용자가 작성한 피드가 빠집니다(목록 개수에 미치는 영향은 각 API 문서 참고). 피드 상세, 댓글, 데일리 메시지 등 그 밖의 API와 비로그인 요청에는 적용되지 않습니다.
* 검사 순서는 회원 존재 여부(404 `MB001`) → 본인 여부(400 `BL101`) → 중복 차단(409 `BL301`)입니다.
* 요청 본문에 `memberId` 가 없거나 `null` 이면 400 `C101` (<<overview-error-response,공통 에러>> 참고)

[[block-member-delete]]
=== 사용자 차단 해제

내가 차단한 사용자의 차단을 해제합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 경로의 `memberId` 에는 <<block-member-list,차단한 사용자 목록 조회>> 응답의 `blockedMemberId`(문자열 사용자 아이디)를 그대로 넣습니다. 차단 기록 ID(`id`)가 아닙니다.
* 회원은 아이디를 바꿀 수 있고 바꾸기 전 아이디는 다른 회원이 새로 쓸 수 있으므로, 항상 목록에서 받은 최신 `blockedMemberId` 를 사용하세요. 예전 아이디로 요청하면 404 `MB001` 이 오거나, 그 아이디를 지금 쓰는 다른 회원 기준으로 처리됩니다.
* `memberId` 에 해당하는 회원이 없으면 404 `MB001`, 회원은 있지만 내가 차단하지 않은 사용자면 404 `BL001` 을 반환합니다.

[[block-member-list]]
=== 차단한 사용자 목록 조회

내가 차단한 사용자 목록을 최근에 차단한 순(차단 일시 내림차순)으로 페이지 단위로 조회합니다. 정렬 방식은 고정이며 정렬 파라미터는 받지 않습니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 내가 차단한 사용자만 포함되며, 나를 차단한 사용자는 포함되지 않습니다.
* `blockedMemberId` · `blockedMemberNickname` · `blockedMemberProfileImage` 는 조회 시점의 현재 회원 정보입니다.
* `totalCount` 는 내가 차단한 전체 사용자 수이고, `hasNext` 는 다음 페이지가 있는지 여부입니다. 다음 페이지 요청 여부는 `hasNext` 로 판단하세요.
* *페이징*: `page` 0 이상, `size` 1~1000. `page` 가 음수면 400 `C103`, `size` 가 범위를 벗어나면 400 `C104`, 숫자가 아니면 400 `C106` (<<overview-error-response,공통 에러>> 참고)

[[block-keyword-create]]
=== 키워드 차단

특정 키워드를 차단합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* *정규화*: 서버는 `keyword` 의 앞뒤 공백을 지우고 소문자로 바꾼 값으로 검증·중복 확인·저장합니다. 응답의 `keyword` 는 이 정규화된 값이라 입력값과 다를 수 있습니다(예: 앞뒤에 공백을 붙인 `SPOILER` → `spoiler`).
* *제한*: 정규화 후 1~50자(UTF-16 코드 유닛 기준이라 대부분의 이모지는 1개가 2자 이상)이며, 사용자당 최대 100개까지 등록할 수 있습니다. `/` 가 들어간 키워드도 등록되지만 <<block-keyword-delete,키워드 차단 해제>>로는 해제할 수 없습니다.
* *적용 범위*: 로그인한 상태에서 <<board-feeds,보드별 피드 목록 조회>>와 <<board-popular-feeds,보드별 인기 피드 목록 조회>>를 호출하면, 제목(`title`)이나 본문(`content`)에 차단 키워드가 들어간 피드가 빠집니다. 대소문자를 구분하지 않는 부분 문자열 비교이며 단어 단위가 아닙니다(예: `스포` 를 차단하면 `스포일러` 가 들어간 피드도 제외). 목록 개수에 미치는 영향은 각 API 문서를 참고하세요. 댓글, 데일리 메시지 등 그 밖의 API와 비로그인 요청에는 적용되지 않습니다.
* 검사 순서는 빈 값(400 `BL103`) → 길이(400 `BL102`) → 중복(409 `BL302`) → 개수 제한(400 `BL104`)입니다. 따라서 100개가 찬 상태에서 이미 등록한 키워드를 다시 보내면 `BL104` 가 아니라 `BL302` 가 반환됩니다.
* 요청 본문에 `keyword` 가 없거나 `null` 이면 400 `C101` (<<overview-error-response,공통 에러>> 참고)
