[[notification-rules]]
=== 알림 생성 규칙

[NOTE]
====
현재 서버 버전에서는 피드 좋아요·댓글 작성 흐름에서 알림 생성이 호출되지 않습니다. 따라서 새 알림이 만들어지지 않고 푸시(FCM)도 발송되지 않습니다. 아래 규칙과 <<notification-push,푸시 메시지 형식>>은 서버에 구현된 알림 생성 로직의 기준입니다.
====

알림은 다른 회원의 행동에 따라 서버가 생성합니다. 클라이언트가 알림을 직접 만드는 API는 없습니다.

* *FEED_LIKE*: 다른 회원이 내 피드에 좋아요를 누르면 생성됩니다.
* *FEED_COMMENT*: 다른 회원이 내 피드에 댓글을 작성하면 생성됩니다.
* 내 피드에 내가 좋아요나 댓글을 남기면 알림이 생성되지 않습니다.
* <<notification-setting-update,알림 설정>>에서 해당 타입을 끄면(설정을 저장한 적이 없으면 켜짐으로 간주) 그 기간의 알림은 저장되지 않습니다. 목록과 읽지 않은 개수에 나타나지 않고 푸시도 발송되지 않으며, 나중에 다시 켜도 복구되지 않습니다.
* 좋아요 취소, 댓글 삭제, 피드 삭제가 일어나도 이미 생성된 알림은 삭제되지 않습니다.
* 발신자가 탈퇴해도 알림은 남으며, 이때 `senderNickname` · `senderProfileImage` 는 `null` 입니다.

[[notification-push]]
=== 푸시(FCM) 메시지 형식

알림이 저장되면 수신자가 <<fcm-token-register,FCM 토큰 등록>>으로 등록한 모든 기기에 FCM 푸시를 보냅니다. 등록된 토큰이 없으면 푸시 없이 알림만 저장됩니다. 발송은 비동기이고, 발송에 실패해도 알림 저장과 API 응답에는 영향이 없습니다.

[cols="1,2,4",options="header"]
|===
| 위치 | 키 | 값

| `notification` | `title` | 알림 타입 설명 (`FEED_LIKE`: `피드 좋아요`, `FEED_COMMENT`: `피드 댓글`)
| `notification` | `body` | 알림의 `content` 와 같은 문구
| `data` | `type` | 알림 타입 (`FEED_LIKE`, `FEED_COMMENT`)
| `data` | `relatedResourceId` | 관련 리소스 ID를 문자열로 변환한 값 (현재는 피드 ID). 없으면 빈 문자열(`+""+`)
| `data` | `relatedResourceType` | 관련 리소스 타입 (현재는 `FEED`). 없으면 빈 문자열(`+""+`)
|===

* `data` 의 값은 모두 문자열이며 `null` 대신 빈 문자열이 옵니다. `relatedResourceId` 는 숫자로 변환해서 사용하세요.
* `data` 에는 알림 ID가 없어 푸시 데이터만으로는 해당 알림을 읽음 처리할 수 없습니다. <<notification-list,알림 목록>>을 다시 조회해 ID를 찾거나 <<notification-mark-all-read,모든 알림 읽음 처리>>를 사용하세요.

[[notification-list]]
=== 알림 목록 조회

로그인한 회원이 받은 알림 전체(읽음·안 읽음 모두)를 생성 일시 최신순(`createdAt` DESC)으로 조회합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* *정렬*: 최신순으로 고정되며 정렬 파라미터는 받지 않습니다. 생성 일시는 초 단위라, 같은 초에 생성된 알림끼리의 순서는 정해져 있지 않습니다.
* *표시 정보*: `content` 는 서버가 만든 완성 문장이라 그대로 표시하면 됩니다. `senderNickname` · `senderProfileImage` 는 조회 시점의 발신자 정보이고, `content` 에 들어 있는 닉네임은 알림 생성 시점의 값입니다.
* *이동*: `relatedResourceType` 이 `FEED` 이면 `relatedResourceId` 로 <<feed-detail,피드 상세 조회>>를 호출합니다. `FEED_COMMENT` 알림도 댓글 ID가 아니라 피드 ID가 옵니다.
* 알림이 없으면 `content` 는 빈 배열입니다.
* *페이징 주의*: offset 기반 페이지네이션입니다. 페이지를 넘기는 사이에 새 알림이 생기면 이미 받은 항목이 다음 페이지에 다시 나올 수 있고, 알림을 삭제하면 일부 항목이 빠질 수 있습니다.
* *페이징*: `page` 0 이상, `size` 1~1000. 범위를 벗어나거나 숫자가 아니면 400 `C103` / `C104` / `C106` (<<overview-pagination,페이지네이션>> 참고)

operation::notification/list/200[snippets='http-request,request-headers,query-parameters,http-response,response-fields']

[[notification-unread-list]]
=== 읽지 않은 알림 목록 조회

로그인한 회원이 받은 알림 중 읽지 않은(`isRead` = `false`) 알림만 생성 일시 최신순(`createdAt` DESC)으로 조회합니다. 응답 형식은 <<notification-list,알림 목록 조회>>와 같습니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* *정렬*: 최신순으로 고정되며 정렬 파라미터는 받지 않습니다. 생성 일시는 초 단위라, 같은 초에 생성된 알림끼리의 순서는 정해져 있지 않습니다.
* *페이징 주의*: offset 기반 페이지네이션입니다. 페이지를 넘기는 사이에 알림을 읽음 처리하면 목록이 앞으로 당겨져, 다음 페이지에서 일부 항목이 빠질 수 있습니다. 반대로 새 알림이 생기면 이미 받은 항목이 다음 페이지에 다시 나올 수 있습니다.
* *페이징*: `page` 0 이상, `size` 1~1000. 범위를 벗어나거나 숫자가 아니면 400 `C103` / `C104` / `C106` (<<overview-pagination,페이지네이션>> 참고)

operation::notification/unread-list/200[snippets='http-request,request-headers,query-parameters,http-response,response-fields']

[[notification-unread-count]]
=== 읽지 않은 알림 개수 조회

로그인한 회원이 받은 모든 타입의 알림 중 읽지 않은 알림 개수를 조회합니다. 뱃지 표시에 사용합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 읽지 않은 알림이 없으면 `data` 는 `0` 입니다.

operation::notification/unread-count/200[snippets='http-request,request-headers,http-response,response-fields']

[[notification-mark-read]]
=== 알림 읽음 처리

로그인한 회원이 받은 알림 하나를 읽음 처리합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 이미 읽은 알림이어도 에러 없이 200을 반환합니다(멱등).
* `notificationId` 에 숫자가 아닌 값을 보내면 400 `C106` (공통 에러 참고)

operation::notification/mark-read/200[snippets='http-request,request-headers,path-parameters,http-response,response-fields']

[[notification-mark-all-read]]
=== 모든 알림 읽음 처리

로그인한 회원이 받은 모든 타입의 읽지 않은 알림을 한 번에 읽음 처리합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 읽지 않은 알림이 없어도 200을 반환합니다. 처리한 알림 개수는 반환하지 않습니다.
* 호출이 끝나면 <<notification-unread-count,읽지 않은 알림 개수>>는 `0` 입니다(호출 이후 새로 생성된 알림은 제외).

operation::notification/mark-all-read/200[snippets='http-request,request-headers,http-response,response-fields']

[[notification-delete]]
=== 알림 삭제

로그인한 회원이 받은 알림 하나를 삭제합니다. 삭제한 알림은 목록과 읽지 않은 개수에서 빠지며 복구할 수 없습니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 같은 알림을 다시 삭제하면 404 `NOTIFICATION_NOT_FOUND` 입니다.
* `notificationId` 에 숫자가 아닌 값을 보내면 400 `C106` (공통 에러 참고)

operation::notification/delete/200[snippets='http-request,request-headers,path-parameters,http-response,response-fields']
