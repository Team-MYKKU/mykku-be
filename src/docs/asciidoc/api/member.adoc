[[member-change-password]]
=== 비밀번호 변경

현재 비밀번호를 확인한 뒤 새 비밀번호로 변경합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료, 탈퇴 회원 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* **이메일로 가입한 회원(`provider` 가 `EMAIL`)만** 사용할 수 있습니다. 소셜 로그인 회원은 비밀번호가 없어 어떤 `currentPassword` 를 보내도 `INVALID_CURRENT_PASSWORD` 가 반환되므로, 소셜 회원에게는 비밀번호 변경 메뉴를 노출하지 않는 것을 권장합니다.
* `currentPassword` 나 `newPassword` 가 비어 있거나 `newPassword` 가 규칙(요청 필드 참고)에 맞지 않으면 400 `INVALID_INPUT` (C101)이 반환되고, `message` 에 사유가 들어갑니다. 여러 항목이 틀리면 사유가 쉼표로 이어집니다.
* `newPassword` 길이 상한은 검증하지 않습니다. 72자를 넘으면 400이 아니라 500 `INTERNAL_SERVER_ERROR` (C402)가 반환되므로 입력을 72자 이하로 제한하세요.
* 응답 `data` 는 항상 빈 객체입니다.

[[member-update-profile]]
=== 프로필 수정

닉네임과 프로필 이미지 URL을 JSON(`Content-Type: application/json`)으로 수정합니다. 이미지 파일을 직접 올리려면 같은 경로에 `multipart/form-data` 로 요청하는 <<member-update-profile-multipart,프로필 수정 (이미지 업로드)>>를 사용하세요.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료, 탈퇴 회원 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 보낸 필드만 변경됩니다. 필드를 생략하거나 `null` 로 보내면 기존 값을 유지합니다.
* `nickname`: 최대 10자, 한글 완성형·영문·숫자·공백만 허용합니다. 현재 닉네임과 같은 값이면 중복 검사 없이 통과합니다.
* `profileImage`: http 또는 https URL, 최대 255자입니다. 빈 문자열(`+""+`)을 보내면 이미지가 제거되어 이후 응답의 `profileImage` 가 빈 문자열이 됩니다. 서버는 전달한 URL을 변환하지 않고 그대로 저장합니다. (요청 예시의 URL 호스트가 `api.dev.mykku.kr` 로 보이는 것은 문서 생성 과정에서 치환된 것입니다.)
* 닉네임 10자 초과, `profileImage` 형식·길이 오류는 400 `INVALID_INPUT` (C101)이며 `message` 에 사유가 들어갑니다.
* 응답은 <<member-get-my-profile,내 프로필 조회>>와 같은 구조입니다. 프로필 설정 전에 호출하면 `memberId` 는 `null` 로 남습니다.

[[member-update-profile-multipart]]
=== 프로필 수정 (이미지 업로드)

`multipart/form-data` 로 닉네임과 프로필 이미지 파일을 함께 수정합니다. 경로(`PATCH /api/v1/members/me`)는 <<member-update-profile,프로필 수정>>과 같고 요청 `Content-Type` 으로 구분됩니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료, 탈퇴 회원 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* 두 파트 모두 선택입니다. 보낸 값만 변경되고 나머지는 기존 값을 유지합니다.
** `request`: 수정할 정보 JSON입니다. 파트의 `Content-Type` 은 `application/json` 이어야 하며, 아니면 415 `UNSUPPORTED_MEDIA_TYPE` (C203)이 반환됩니다. 필드 규칙은 <<member-update-profile,프로필 수정>>과 같습니다.
** `profileImage`: 이미지 파일입니다. 비어 있지 않은 파일을 보내면 업로드 후 그 URL로 프로필 이미지가 변경되고, `request` 파트의 `profileImage` URL은 무시됩니다. 빈 파일이면 파일은 무시되고 `request` 파트의 `profileImage` 값이 적용됩니다.
* 이미지 파일 규칙: 확장자 jpg, jpeg, png, gif (대소문자 무관). 파일 형식은 파트의 `Content-Type` 이 아니라 파일명 확장자로 판단합니다. webp 확장자는 확장자 검사는 통과하지만 현재 서버에서 이미지로 읽지 못해 `IMAGE_UNREADABLE` 이 반환됩니다. 파일이 10MB를 넘으면 413 `PAYLOAD_TOO_LARGE` (C205)가 반환됩니다.
* 이미지로 인식되지만 내용이 손상된 파일은 500 `IMAGE_SIZE_EXTRACTION_FAILED` (IM401)이 반환될 수 있습니다.
* 닉네임 10자 초과, `request` 파트의 `profileImage` 형식·길이 오류는 400 `INVALID_INPUT` (C101), multipart 형식 자체가 잘못되면 400 `INVALID_MULTIPART_REQUEST` (C107)입니다.
* 응답은 <<member-get-my-profile,내 프로필 조회>>와 같은 구조입니다.
* 요청 예시의 `Content-Type` 헤더에 `boundary` 가 두 번 보이는 것은 문서 생성 도구 때문입니다. 실제 요청은 HTTP 클라이언트가 만드는 `multipart/form-data; boundary=...` 헤더 하나면 됩니다.

[[member-setup-profile]]
=== 프로필 설정

회원가입(소셜 로그인 또는 이메일 가입) 직후 아이디(`memberId`)와 닉네임을 설정합니다. 설정 전에는 <<member-get-my-profile,내 프로필 조회>>의 `memberId` 와 `nickname` 이 `null` 입니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료, 탈퇴 회원 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* `memberId`: 영문 대소문자·숫자만, 최대 16자. 이미 사용 중인 아이디(대소문자 구분 없이 비교)면 `MEMBER_ID_ALREADY_EXISTS` 입니다. 입력 중 확인은 <<member-check-id,아이디 중복 확인>>을 사용하세요.
* 프로필을 이미 설정한 회원도 다시 호출할 수 있습니다. 이때 중복 검사에서 본인을 제외하지 않으므로 현재 아이디를 그대로 보내면 `MEMBER_ID_ALREADY_EXISTS` 입니다. 설정 이후 아이디만 바꾸려면 <<member-change-member-id,아이디 변경>>을 사용하세요.
* `nickname`: 한글 완성형·영문·숫자·공백만, 최대 10자(공백만으로는 불가). 이 API는 닉네임 중복을 검사하지 않으므로 다른 회원과 같은 닉네임도 설정됩니다.
* 형식 오류(빈 값, 길이 초과, 허용 외 문자)는 400 `INVALID_INPUT` (C101)이며 `message` 에 사유가 들어갑니다. 여러 항목이 틀리면 사유가 쉼표로 이어집니다(예: "아이디는 영문과 숫자만 사용 가능합니다, 닉네임은 최대 10자까지 가능합니다").
* 응답 `role` 은 대표 칭호입니다. 가입 시 '첫 만남' 칭호가 비동기로 지급되어 대표로 지정되므로 보통 값이 있지만, 지급 전이거나 대표 칭호가 없으면 `null` 입니다.

[[member-withdraw]]
=== 회원 탈퇴

회원 탈퇴를 즉시 처리합니다. 별도 확인 절차 없이 회원 정보가 영구 삭제되며 되돌릴 수 없습니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면(만료, 탈퇴 회원 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고)
* *남는 데이터*: 작성한 피드, 피드 댓글, 하루 덕담 댓글, 이벤트·콘테스트 참여 기록, 다른 회원에게 보낸 알림. 이 데이터를 조회하면 작성자·발신자 정보가 `null` 로 내려가므로(예: 피드·피드 댓글의 `author`), '탈퇴한 회원' 표시는 클라이언트에서 처리해야 합니다. API별 표현은 <<overview-empty-values,탈퇴 회원과 빈 값>>을 참고하세요.
* *삭제되는 데이터*: 좋아요(피드·피드 댓글·하루 덕담 댓글 좋아요, 게시판 즐겨찾기), 취향 설정, 받은 알림, 알림 설정, FCM 토큰, 보유 칭호, 칭호 획득용 활동 집계, 차단 목록(내가 차단한 회원·키워드, 다른 회원이 나를 차단한 기록), 내가 한 신고.
* 탈퇴 후 기존 액세스 토큰으로 인증이 필요한 API를 호출하면 401 `AU201`, 리프레시 토큰으로 재발급을 요청하면 404 `MEMBER_NOT_FOUND` (MB001)가 반환됩니다. 204 응답을 받으면 클라이언트에 저장된 토큰을 삭제하세요.
* 같은 소셜 계정이나 이메일로 다시 가입하면 이전 데이터와 연결되지 않은 새 회원으로 생성되며, <<member-setup-profile,프로필 설정>>부터 다시 진행합니다.
