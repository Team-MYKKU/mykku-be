[[error-code-list]]
=== 에러 코드 전체 조회

서버에 정의된 에러 코드 목록 전체를 조회합니다.

* *인증 불필요*: `Authorization` 헤더를 사용하지 않습니다.
* 경로에 `/v1` 이 없습니다(`/api/error-codes`).
* *정렬*: `code` 의 문자열 오름차순입니다(예: `AD001`, `AD101`, ..., `AU101`, ...).
* `code` 는 에러 응답 본문의 `code` 와 같은 값이고, `name` 은 각 API 문서 *에러 응답* 항목 제목의 에러 이름과 같습니다. 클라이언트 분기는 `code` 로 하세요.
* `message` 는 기본 메시지입니다. 실제 응답의 `message` 와 다를 수 있으므로(예: `C101` 검증 실패는 필드별 메시지) 표시용으로만 쓰세요.
* 관리자 전용 코드(`AD`)도 포함됩니다. 신고(`RP`) 코드는 현재 이 목록에 포함되어 있지 않으므로 <<report-api>> 문서의 에러 응답을 참고하세요.
* 정의되어 있어도 현재 어떤 API도 반환하지 않는 코드가 있습니다. 각 API가 반환하는 에러는 해당 API 문서의 *에러 응답* 항목과 <<overview-common-errors>>를 기준으로 하세요.

[[error-code-domains]]
=== 에러 코드 도메인 목록 조회

에러 코드 목록의 도메인 키를 사전순으로 조회합니다.

* *인증 불필요*: `Authorization` 헤더를 사용하지 않습니다.
* 도메인 키는 camelCase 문자열(예: `dailyMessage`, `fanNote`)이며 대소문자를 구분합니다. <<error-code-by-domain>>의 경로 값으로 그대로 씁니다.

operation::error-code/domains/200[snippets='http-request,http-response,response-fields']

[[error-code-by-domain]]
=== 도메인별 에러 코드 조회

특정 도메인의 에러 코드 목록을 조회합니다.

* *인증 불필요*: `Authorization` 헤더를 사용하지 않습니다.
* *정렬*: 서버에 정의된 순서입니다. `code` 순이 아닐 수 있습니다(<<error-code-list>>와 다름).
* 없는 도메인 키이거나 대소문자가 다른 키를 보내면 404가 아니라 `200` 과 빈 배열(`data: []`)을 반환합니다(<<error-code-by-domain-empty>>).
* 응답 항목의 필드는 <<error-code-list>>와 같습니다.

operation::error-code/by-domain/200[snippets='http-request,path-parameters,http-response,response-fields']
