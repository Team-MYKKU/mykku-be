[[notification-setting-list]]
=== 알림 설정 목록 조회

로그인한 회원의 알림 타입별 수신 설정을 조회합니다.

* *인증 필요* (<<overview-error-response,공통 에러>> 참고)
* 응답에는 항상 모든 알림 타입(현재 `FEED_LIKE`, `FEED_COMMENT`)이 1건씩 포함됩니다. 설정을 저장한 적이 없는 회원도 빈 배열을 받지 않습니다. 각 타입의 알림이 언제 생성되는지는 <<notification-rules,알림 생성 규칙>>을 참고하세요.
* 저장된 설정이 없는 타입은 이 조회 시점에 기본값 `isEnabled: true`(수신)로 생성·저장된 뒤 함께 반환됩니다(조회 API지만 설정이 저장될 수 있음).
* 배열 순서는 보장되지 않습니다. `notificationType` 으로 항목을 매칭해 주세요.
* 서버에 새 알림 타입이 추가되면 별도 작업 없이 목록에 포함됩니다. 모르는 `notificationType` 은 무시하거나 기본 라벨로 표시해 주세요.
* 설정은 기기별이 아니라 계정 단위이며, 등록된 모든 기기에 함께 적용됩니다.
* 설정이 저장되지 않은 타입이 있는 상태에서 이 API나 <<notification-setting-update,알림 설정 변경>>을 동시에 여러 번 호출하면 일부 요청이 409 `C302` 로 실패할 수 있습니다. 다시 호출하면 정상 응답합니다.

operation::notification-setting/list/200[snippets='http-request,request-headers,http-response,response-fields']

[[notification-setting-update]]
=== 알림 설정 변경

알림 타입 하나의 수신 여부를 변경합니다.

* *인증 필요* (<<overview-error-response,공통 에러>> 참고)
* 한 번에 한 타입만 변경합니다. 설정은 설정 ID(`id`)가 아니라 `notificationType` 으로 식별하며, 저장된 설정이 없으면 요청한 `isEnabled` 값으로 새로 생성합니다.
* 같은 값으로 다시 요청해도 정상(200) 응답합니다.
* `notificationType` 은 대소문자를 구분합니다. 목록에 없는 값(예: `feed_like`)이나 누락·`null` 은 400 `C101` 입니다(`NF102` 는 반환되지 않음).
* `isEnabled` 를 생략하거나 `null` 로 보내면 400이 아니라 `false`(끄기)로 처리됩니다. 항상 `true`/`false` 를 명시해 주세요.
* `isEnabled: false` 인 타입의 알림은 생성되지 않습니다. 즉 <<notification-list,알림 목록>>에 저장되지 않고 푸시(FCM)도 발송되지 않으며, 다시 켜도 꺼져 있던 동안의 알림은 복구되지 않습니다.
* 변경은 즉시 적용되어 이후 발생하는 알림부터 반영되며, 이미 저장된 알림에는 영향이 없습니다. 계정 단위 설정이므로 모든 기기에 적용됩니다.
* 여러 타입을 한 번에 켜거나 끄는 API는 없습니다. 전체 켜기/끄기 토글은 알림 타입마다(`FEED_LIKE`, `FEED_COMMENT`) 이 API를 각각 호출해 주세요.

operation::notification-setting/update/200[snippets='http-request,request-headers,request-fields,http-response,response-fields']
