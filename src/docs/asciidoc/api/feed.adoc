[[feed-create]]
=== 피드 작성

새 피드를 작성합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고). 아이디와 닉네임을 설정하지 않은 회원은 작성할 수 없습니다 (`PROFILE_NOT_COMPLETED`).
* 요청은 `multipart/form-data` 형식입니다.
** `request` 파트 (필수): JSON이며 파트의 `Content-Type` 은 `application/json` 이어야 합니다 (아니면 415 `C203`). 필드는 아래 *request 파트 필드* 표를 참고하세요. 파트가 없으면 400 `C105`, `title` · `content` 가 없거나 공백이면, `content` 가 1000자를 넘거나 `tags` 가 8개 이상이면 400 `C101` 입니다 (<<overview-error-response,공통 에러>> 참고).
** `images` 파트 (선택): 이미지 파일. 같은 파트 이름으로 여러 번 보내며 최대 10개입니다.

*이미지 파일 규칙*

* 형식은 파일명의 확장자로 판별합니다 (`jpg`, `jpeg`, `png`, `gif`, `webp`, 대소문자 무관). 그 외 확장자이거나 파일명에 확장자가 없으면 `IMAGE_INVALID_FORMAT` 입니다.
* 서버가 이미지를 디코딩해 가로·세로 크기(px)를 저장합니다. 이미지 형식으로 인식할 수 없는 파일은 `IMAGE_UNREADABLE` 입니다. `webp` 는 확장자 검사는 통과하지만 현재 서버에서 디코딩되지 않아 `IMAGE_UNREADABLE` 로 거절됩니다. 형식은 인식되지만 데이터가 손상된 파일은 500 `IMAGE_SIZE_EXTRACTION_FAILED` (IM401)이 될 수 있습니다.
* 크기가 0 bytes인 파일은 `IMAGE_FILE_EMPTY` 입니다.
* 파일 하나가 10MB, 요청 전체가 50MB를 넘으면 413 `C205` (`PAYLOAD_TOO_LARGE`) 입니다 (개발 서버 기준, <<overview-error-response,공통 에러>> 참고).

*태그 규칙*

* 최대 7개입니다. 개수는 서버의 정리 전, 요청 배열 기준으로 검사합니다.
* 서버는 각 태그의 앞뒤 공백을 제거하고, 빈 문자열을 제외하고, 중복을 제거한 뒤 저장합니다. 영문 대소문자는 구분해 그대로 저장합니다.
* 각 태그는 1자 이상 20자 이하이며 한글(완성형), 영문, 숫자만 사용할 수 있습니다. 공백, 특수문자, 이모지, 자음/모음 단독(예: `ㅋㅋ`)은 사용할 수 없으며, 태그 앞에 `+#+` 을 붙이지 않고 보내야 합니다. 20자를 넘으면 `TAG_TITLE_TOO_LONG`, 형식을 위반하면 `TAG_INVALID_FORMAT` 입니다.

*콘테스트 자동 참여*

* 상태가 `ACTIVE` 이고 마감 일시(`expiredAt`)가 지나지 않은 콘테스트의 태그(<<contest-detail,콘테스트 상세 조회>>의 `data.tags`)를 *모두* 포함해 피드를 작성하면, 해당 콘테스트에 자동으로 참여 처리됩니다. 별도의 콘테스트 참여 API는 없습니다.
* 시작 일시(`startedAt`)는 확인하지 않으므로 시작 전인 콘테스트도 대상입니다. 태그가 없는 콘테스트는 대상이 아닙니다.
* 태그는 앞뒤 공백 제거 후 대소문자까지 정확히 일치해야 합니다. 여러 콘테스트의 조건을 동시에 만족하면 모두 참여 처리됩니다.
* 참여 여부는 피드 작성 시에만 판단하며, 작성 응답에는 참여 결과가 포함되지 않습니다. 피드 수정으로 태그를 바꿔도 참여가 새로 등록되거나 취소되지 않습니다.

*응답*

작성 응답의 구조는 <<feed-detail,피드 상세 조회>>와 다릅니다. 작성자 정보가 `author` 객체가 아니라 `authorId` / `authorNickname` / `authorProfileUrl` 로 펼쳐져 있고, 칭호(`role`), `isLiked`, `updatedAt` 이 없으며, `tags` 는 `isContest` 가 없는 문자열 배열입니다. 상세 화면 모델이 필요하면 반환된 `data.id` 로 피드 상세 조회를 호출하세요.

[[feed-detail]]
=== 피드 상세 조회

특정 피드의 상세 정보를 조회합니다.

* 로그인 없이 조회할 수 있습니다. `Authorization` 헤더를 보내면 `isLiked` 가 해당 회원 기준으로 계산되고, 헤더가 없거나 토큰이 유효하지 않으면 401 없이 비로그인으로 처리되어 `isLiked` 는 항상 `false` 입니다.
* 작성자가 탈퇴한 피드는 `author` 가 `null` 입니다.
* `tags[].isContest` 는 태그 제목이 어떤 콘테스트의 태그와 일치하는지만 나타내며, 콘테스트 상태나 이 피드의 실제 참여 여부와는 관계없습니다.

[[feed-comments]]
=== 피드 댓글 목록 조회

특정 피드의 댓글 목록을 대댓글과 함께 조회합니다.

* 로그인 없이 조회할 수 있습니다. `Authorization` 헤더를 보내면 댓글·대댓글의 `isLiked` 가 해당 회원 기준으로 계산되고, 헤더가 없거나 토큰이 유효하지 않으면 401 없이 비로그인으로 처리되어 `isLiked` 는 모두 `false` 입니다.
* 최상위 댓글은 최신순(`createdAt` 내림차순)으로 페이지 단위로 반환됩니다. `page` / `size` 와 `totalElements` / `totalPages` / `hasNext` 는 최상위 댓글 기준이며, 정렬 기준은 바꿀 수 없습니다.
* 각 댓글의 대댓글은 페이지네이션 없이 전부 오래된 순(`createdAt` 오름차순)으로 `replies` 에 포함됩니다. `replyCount` 는 `replies` 배열의 길이와 같습니다.
* 작성자가 탈퇴한 댓글과 대댓글은 목록에 포함되지 않습니다 (탈퇴한 회원의 최상위 댓글에 달린 대댓글도 함께 제외). 이때 `totalElements` / `totalPages` 는 제외된 최상위 댓글까지 센 값이라 실제로 반환되는 댓글 수보다 클 수 있습니다.
* `page` 는 0 이상, `size` 는 1 이상 1000 이하입니다. 범위를 벗어나면 400 `C103` / `C104`, 숫자가 아니면 400 `C106` 입니다 (<<overview-error-response,공통 에러>> 참고).

[[feed-update]]
=== 피드 수정

기존 피드의 제목, 내용, 태그, 이미지를 수정합니다.

* *인증 필요*: 토큰이 없거나 유효하지 않으면 401 `AU201` (<<overview-error-response,공통 에러>> 참고). 작성자만 수정할 수 있습니다 (`FEED_FORBIDDEN_ACCESS`).
* 요청은 `multipart/form-data` 형식입니다.
** `request` 파트 (필수): JSON이며 파트의 `Content-Type` 은 `application/json` 이어야 합니다 (아니면 415 `C203`). 모든 필드는 선택이며, 보내지 않거나 `null` 이면 기존 값을 유지합니다. 파트가 없으면 400 `C105`, `content` 가 1000자를 넘거나 `tags` 가 8개 이상이면 400 `C101` 입니다 (<<overview-error-response,공통 에러>> 참고). `title` · `content` 는 빈 문자열도 검사 없이 그대로 저장됩니다.
** `images` 파트 (선택): 새로 추가할 이미지 파일. 파일 규칙은 <<feed-create,피드 작성>>과 같습니다.
* `boardId` 는 현재 저장에 반영되지 않습니다. 값과 관계없이 피드는 작성 시의 게시판에 그대로 남고, 응답의 `boardId` 도 기존 값입니다.
* `tags` 를 보내면 기존 태그 전체가 보낸 목록으로 교체되고, 빈 배열이면 모든 태그가 삭제됩니다. 태그 규칙은 <<feed-create,피드 작성>>과 같습니다. 태그를 바꿔도 콘테스트 참여는 새로 등록되거나 취소되지 않습니다.
* `deleteImageIds` 에는 이 피드의 이미지 ID만 중복 없이 넣어야 합니다. 다른 피드의 이미지 ID, 존재하지 않는 ID, 중복 ID가 있으면 `FEED_IMAGE_NOT_FOUND` 입니다.
* 수정 후 이미지 수(기존 이미지 수 − `deleteImageIds` 개수 + 새 이미지 수)가 10개를 넘으면 `FEED_IMAGE_LIMIT_EXCEEDED` 입니다.
* 응답 구조는 <<feed-detail,피드 상세 조회>>와 같으며, `author` 는 요청한 회원 본인입니다.
