[[daily-message-list]]
=== 하루 덕담 목록 조회

기준 날짜(`date`) 당일을 포함해 그 이전 날짜에 배정된 하루 덕담을 페이지 단위로 조회합니다.

* *인증 불필요*: `Authorization` 헤더 없이 호출합니다.
* *정렬*: 덕담 날짜(`date`) 내림차순(최신 날짜 먼저)으로 고정되며, 정렬 파라미터는 없습니다. 날짜마다 덕담은 최대 1개입니다.
* *기준 날짜*: 서버는 `date` 를 오늘로 제한하지 않습니다. 미래 날짜를 보내면 그 날짜까지 미리 등록된 덕담도 포함되므로, 오늘까지의 덕담만 보여주려면 오늘 날짜(KST)를 보냅니다.
* *페이징*: `data.number`(현재 페이지, 0부터 시작), `data.size`(요청한 페이지 크기), `data.totalElements`, `data.totalPages`, `data.last`(true이면 다음 페이지 없음)를 사용하세요. `data.pageable`, `data.sort` 객체는 같은 값을 중복해 담은 Spring 메타 정보입니다.
* 마지막 페이지를 넘는 `page` 를 요청하면 에러 없이 `data.content` 가 빈 배열로 반환됩니다.
* *입력 오류*(모두 400, <<overview-error-response,공통 에러>> 참고): `date` 누락 시 `C105`, `date` 가 `yyyy-MM-dd` 형식이 아니거나 `page` / `size` 가 숫자가 아니면 `C106`, `page` 가 0 미만이면 `C103`, `size` 가 1~1000 범위 밖이면 `C104`.

[[daily-message-detail]]
=== 하루 덕담 상세 조회

하루 덕담 1건의 상세 정보를 조회합니다. `id` 는 목록 조회 응답의 `data.content[].id` 값입니다.

* *선택 인증*: `Authorization` 헤더 없이도 호출할 수 있고, 응답 내용은 로그인 여부와 관계없이 같습니다. 토큰이 없거나 만료·위조 등으로 유효하지 않아도 401 없이 비로그인으로 처리됩니다.
* *칭호 집계*: 유효한 토큰으로 조회에 성공하면 호출할 때마다 하루 덕담 조회 횟수가 1회 쌓입니다. 같은 덕담을 다시 조회해도 중복 제거 없이 매번 쌓이며, 비로그인 조회와 에러 응답(404 등)은 집계되지 않습니다. 누적 1 / 15 / 30회에 각각 '행운은 나의 것!' / '덕질의 가호' / '콘텐츠 섭렵' 칭호가 자동으로 부여됩니다.
* 미리 불러오기(프리패치)로 호출해도 조회로 집계되므로, 사용자가 실제로 덕담을 열람할 때 호출하세요.
* 조회 횟수 집계와 칭호 부여는 요청 처리 후 비동기로 이루어지므로 이 API 응답에는 칭호 정보가 없습니다. 새로 받은 칭호는 <<role-new-roles,새로 획득한 칭호 조회>> 로 확인합니다.
* `id` 는 숫자 ID입니다. 숫자가 아니면 400 `C106` (<<overview-error-response,공통 에러>> 참고)
