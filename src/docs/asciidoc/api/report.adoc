[[report-create]]
=== 콘텐츠 신고

피드 게시글(콘테스트 참여작 포함) 또는 피드 댓글·답글을 신고합니다.

* *인증 필요*: 로그인 회원만 신고할 수 있습니다. 토큰이 없거나 유효하지 않으면(만료 포함) 401 `AU201` (<<overview-error-response,공통 에러>> 참고).
* *신고 대상*: `targetType` 이 `FEED` 면 피드 ID를, `FEED_COMMENT` 면 피드 댓글 또는 답글 ID를 `targetId` 로 보냅니다. 데일리 메시지 댓글, 덕질노트, 회원은 신고할 수 없습니다. 작성자가 탈퇴한 콘텐츠도 신고할 수 있으며, 이때 응답의 `targetMemberId` 는 `null` 입니다.
* *처리 방식*: 신고는 관리자 검토 대기(`PENDING`) 상태로 접수될 뿐이며, 신고한 콘텐츠가 자동으로 숨겨지거나 삭제되지 않습니다 (신고자에게도 계속 노출됨). 관리자가 검토 후 `RESOLVED`(처리 완료) 또는 `REJECTED`(반영되지 않음)로 변경합니다.
* *중복 신고*: 같은 회원은 같은 대상(`targetType` + `targetId`)을 한 번만 신고할 수 있고, 신고가 처리(`RESOLVED` / `REJECTED`)된 뒤에도 다시 신고할 수 없습니다. 신고 여부를 조회하는 API나 피드 응답 필드는 없으므로, 이미 신고한 대상인지는 `ALREADY_REPORTED`(409, RP301) 응답으로 판단합니다. 같은 요청이 거의 동시에 두 번 전송되면 드물게 RP301 대신 409 C302가 반환되며, 이 경우도 이미 신고된 것으로 처리하면 됩니다.
* *자신의 콘텐츠*: 자신이 작성한 피드·댓글은 신고할 수 없습니다.
* *상세 내용*: `detail` 은 앞뒤 공백을 제거해 저장하며, 공백만 보내면 입력하지 않은 것으로 처리합니다. `reason` 이 `ETC` 면 필수이고 그 외 사유에서는 선택입니다. 500자 제한은 공백 제거 전 원문 기준이며, 초과하면 400 `C101` 이 반환됩니다 (<<overview-error-response,공통 에러>> 참고).
* *검증 순서*: 인증 → 요청 형식(400 C101: 필수 값 누락, `targetId` 가 1 미만이거나 정수가 아님, 정의되지 않은 enum 값, `detail` 500자 초과) → 신고 대상 존재(RP002) → 자신의 콘텐츠 여부(RP101) → 중복 신고(RP301) → `ETC` 상세 내용(RP102) 순서로 확인하며, 가장 먼저 걸린 에러 하나만 반환됩니다.

[[report-reasons]]
=== 신고 사유 목록 조회

신고 시 선택할 수 있는 사유 목록을 조회합니다.

* *인증 불필요*: 비회원도 호출할 수 있으며, `Authorization` 헤더를 보내도 무시됩니다.
* *반환 순서*: 페이징 없이 전체 사유를 항상 같은 순서로 반환하며, 마지막은 `ETC`(기타)입니다.
* *사용 방법*: `reason` 값을 콘텐츠 신고 API의 `reason` 에 그대로 보내고, `description` 은 화면 표시용 라벨로 사용합니다. `ETC` 를 선택하면 신고 요청에 `detail` 을 반드시 포함해야 합니다.
