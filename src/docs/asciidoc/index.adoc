[[overview-authentication]]
=== 인증

API는 인증 수준에 따라 세 가지로 나뉩니다. 각 API 문서의 *요청 헤더* 표로 구분합니다.

[cols="1,2,4"]
|===
|인증 수준|문서 표기|동작

|필수
|요청 헤더 표에 `Authorization` 이 필수 `O`
|유효한 액세스 토큰이 없으면 `401` `AU201` 을 반환합니다(<<overview-unauthorized>>).

|선택
|요청 헤더 표에 `Authorization` 이 필수 `X`
|토큰 없이 호출할 수 있습니다. 유효한 토큰을 보내면 로그인 회원 기준으로 응답합니다(좋아요 여부, 차단 필터, 칭호 획득 활동 집계 등). 토큰이 없거나 유효하지 않으면(만료 포함) *401 없이* 비로그인으로 처리됩니다.

|불필요
|요청 헤더 표가 없음
|토큰을 보내도 사용하지 않습니다.
|===

헤더 형식은 다음과 같습니다.

[source,http]
----
Authorization: Bearer {accessToken}
----

* 값은 `Bearer` 와 공백 한 칸으로 시작해야 합니다(대소문자 구분). 형식이 다르면 토큰이 없는 것으로 처리됩니다.
* `Authorization` 헤더에는 액세스 토큰만 넣습니다. 리프레시 토큰을 넣으면 유효하지 않은 토큰으로 처리됩니다.
* 인증 선택 API는 다음과 같습니다: <<board-feeds>>, <<board-popular-feeds>>, <<feed-detail>>, <<feed-comments>>, <<daily-message-detail>>, <<daily-message-comment-list>>, <<fan-note-detail>>. 만료된 토큰을 보내도 에러 없이 비로그인 응답이 오므로, 로그인 상태라면 유효한 토큰을 보내세요.

[[overview-unauthorized]]
==== 인증 실패 (401 AU201)

인증 필수 API는 다음 경우에 모두 같은 응답(`401`, code `AU201`)을 반환합니다. 토큰 만료만 따로 구분하는 코드는 없습니다.

* `Authorization` 헤더가 없거나 값이 `Bearer` 와 공백 한 칸으로 시작하지 않음
* 토큰 서명이 올바르지 않거나 토큰이 만료됨
* 액세스 토큰이 아닌 토큰(리프레시 토큰)을 보냄
* 토큰의 회원이 존재하지 않음 (탈퇴 등)

include::{snippets}/common/UNAUTHORIZED/http-response.adoc[]

[[overview-token]]
==== 토큰 발급과 갱신

* 토큰은 <<auth-mobile-login>>, <<email-auth-signup>>, <<email-auth-login>> 응답으로 발급됩니다.
* 유효 기간 필드 `accessTokenExpiresIn`, `refreshTokenExpiresIn` 은 발급 시점부터의 *기간* 이며 단위는 밀리초(ms)입니다(예: `86400000` = 24시간). 만료 시각(epoch)이 아니므로 "응답을 받은 시각 + 값"으로 만료 시점을 계산하세요. <<auth-refresh>> 응답에서는 액세스 토큰 유효 기간 필드 이름이 `expiresIn` 입니다(의미는 `accessTokenExpiresIn` 과 같음). 값은 서버 설정에 따라 달라질 수 있으니 고정값으로 가정하지 마세요.
* 인증 필수 API가 `AU201` 을 반환하면 <<auth-refresh>>로 토큰을 재발급받은 뒤 원래 요청을 다시 보내세요. 재발급 응답에는 새 리프레시 토큰도 들어 있으므로 저장된 액세스 토큰과 리프레시 토큰을 모두 교체하세요.
* 재발급이 401(리프레시 토큰이 유효하지 않거나 만료됨, 또는 리프레시 토큰이 아님) 또는 404 `MB001`(토큰의 회원이 없음)로 실패하면 다시 로그인해야 합니다.
* <<auth-logout>>은 서버에서 토큰을 무효화하지 않고 해당 기기의 FCM 토큰만 삭제합니다. 저장된 토큰은 클라이언트가 삭제하세요.

[[overview-request-id]]
=== 요청 ID (X-Request-ID)

모든 응답에는 `X-Request-ID` 헤더가 포함됩니다. 요청에 `X-Request-ID` 헤더를 보내면 그 값을 그대로 쓰고, 보내지 않으면 서버가 8자리 ID를 만듭니다. 서버 로그가 이 값으로 기록되므로 오류를 문의할 때 함께 전달해 주세요. 문서의 요청·응답 예시에서는 이 헤더를 생략했습니다.

[[overview-response]]
=== 공통 응답 구조

성공 응답 본문은 다음 구조입니다.

[source,json]
----
{
  "message": "응답 메시지",
  "data": { }
}
----

* `data` 는 API에 따라 객체 또는 배열입니다.
* 반환할 데이터가 없는 API는 `data` 가 `null` 이 아니라 빈 객체 `{}` 입니다(예: <<auth-logout>>).
* `204 No Content` 응답(<<member-withdraw>>)은 본문이 없습니다.
* `message` 는 사람이 읽는 안내 문구입니다. API마다 다르고 바뀔 수 있으므로 분기에 쓰지 마세요.
* 값이 없는 필드는 생략되지 않고 `null` 로 내려옵니다.

[[overview-field-table]]
=== 표 읽는 법

* *요청* 표(필드, 경로·쿼리 파라미터, 파트)의 필수 `O` 는 반드시 보내야 하는 값이고, `X` 는 생략할 수 있는 값입니다. 생략하면 설명에 적힌 기본값이 적용됩니다.
* *응답* 필드 표의 필수 `O` 는 항상 `null` 이 아닌 값이 있다는 뜻이고, `X` 는 값이 `null` 이거나 상위 객체·배열이 비어 있어 나타나지 않을 수 있다는 뜻입니다.
* 경로·쿼리 파라미터와 요청 파트 표에는 타입 열이 없으므로 형식은 설명을 참고하세요. 경로의 `+{id}+`, `+{...Id}+` 는 숫자(Long) ID입니다. 예외로 `+{memberId}+`(회원 아이디 문자열), `+{deviceId}+`, `+{keyword}+`, `+{domain}+` 은 문자열이며, URL 인코딩해서 보내야 합니다. 숫자 자리에 숫자가 아닌 값을 보내면 `400` `C106` 입니다.

[[overview-identifier]]
=== 식별자

* `memberId` 와 회원 아이디 필드(`authorId`, `blockedMemberId`, `reporterMemberId`, `targetMemberId`)는 DB의 숫자 ID가 아니라 회원이 정한 *문자열 아이디* 입니다(영문·숫자, 최대 16자).
* 회원 아이디는 프로필 설정(<<member-setup-profile>>) 전에는 `null` 이고, <<member-change-member-id>>로 바뀔 수 있습니다. 영구 식별자나 캐시 키로 쓰지 마세요. 프로필 설정 여부는 로그인 응답의 `isProfileComplete` 로 알 수 있으며, 프로필 설정 전에는 피드·댓글 작성 등 일부 API가 `403` `MB201` 을 반환합니다.
* 그 밖의 ID(`id`, `feedId`, `boardId`, `commentId` 등)는 숫자(Long)입니다. 예외로 FCM 토큰 API의 `deviceId` 는 클라이언트가 정한 기기 식별 문자열입니다.

[[overview-empty-values]]
=== 탈퇴 회원과 빈 값

* 프로필 이미지가 없는 회원(이메일 가입, Apple 로그인, 소셜 계정에 이미지가 없는 경우 등)의 `profileImage` 는 `null` 이 아니라 빈 문자열(`+""+`)일 수 있습니다. `null` 과 `+""+` 를 모두 "이미지 없음"으로 처리하세요.
* 회원이 탈퇴해도 작성한 콘텐츠는 남고, 작성자 정보는 API별로 아래처럼 내려옵니다. 서버는 "탈퇴한 회원" 같은 대체 문구나 기본 이미지를 내려주지 않으므로 클라이언트에서 표시하세요.

[cols="2,3"]
|===
|API|탈퇴한 작성자 표현

|게시판별 피드 목록, 피드 상세
|`author` 가 `null`

|게시판별 피드 목록의 첫 댓글 미리보기
|`comment.profileImage` 가 `null`

|피드 댓글 목록
|댓글·답글의 `author` 가 `null`

|하루 덕담 댓글 목록
|`memberId`, `memberName`, `role`, `profileImage` 가 각각 `null`

|수상작 상세
|`authorNickname` 이 `+""+`, `authorProfileImage` 가 `null`

|이벤트 당첨자 목록
|`memberId`, `nickname` 이 `null`, `profileImage` 가 `+""+`

|알림 목록
|`senderNickname`, `senderProfileImage` 가 `null`
|===

[[overview-datetime]]
=== 날짜·시간 형식

* 일시(`LocalDateTime`): ISO-8601 `+yyyy-MM-dd'T'HH:mm:ss[.소수 초]+` 형식이며 타임존 오프셋이 없습니다. 모든 값은 한국 표준시(KST, UTC+9) 기준이므로 UTC로 해석하지 마세요. 소수 초는 없거나 최대 9자리까지 자릿수가 가변입니다(예: `2025-01-01T00:00:00`, `2026-09-24T14:15:48.03174`). 가변 소수부를 허용하는 파서를 쓰세요.
* 날짜(`LocalDate`): `yyyy-MM-dd` (예: `2025-10-10`).
* 요청에 보내는 날짜·일시도 같은 형식입니다. 쿼리 파라미터(예: <<daily-message-list>>의 `date`) 형식이 틀리면 `400` `C106`, 요청 본문 형식이 틀리면 `400` `C101` 입니다.
* 필드 설명의 "KST, ISO-8601" 표기는 이 규칙을 따른다는 뜻입니다.
* 토큰 유효 기간 값(`accessTokenExpiresIn`, `refreshTokenExpiresIn`, `expiresIn`)은 밀리초(ms) 단위 정수입니다.

[[overview-enum]]
=== enum 값

* 요청·응답의 enum 값은 문서에 적힌 대문자 상수명 문자열(예: `ACTIVE`, `LATEST`, `GOOGLE`)을 그대로 쓰며 대소문자를 구분합니다. `active` 처럼 대소문자가 다르면 정의되지 않은 값으로 처리됩니다.
* 정의되지 않은 값을 쿼리·경로 파라미터로 보내면 `400` `C106`, JSON 본문으로 보내면 `400` `C101`(message: "입력값이 올바르지 않습니다")을 반환합니다.
* 응답의 enum 필드도 상수명으로 내려옵니다. 화면 표시용 한글 라벨은 따로 내려주지 않으므로 각 필드 설명의 값 목록을 참고해 클라이언트에서 매핑하세요. 예외로 <<report-create>> 응답의 `...Description` 필드와 <<report-reasons>> 응답의 `description` 은 한글 라벨입니다.

[[overview-pagination]]
=== 페이지네이션

페이지 단위로 조회하는 목록 API는 쿼리 파라미터 `page`, `size` 를 받습니다. 두 파라미터는 생략할 수 있습니다.

[cols="1,1,4"]
|===
|파라미터|기본값|규칙

|`page`
|`0`
|0부터 시작하는 페이지 번호. 0 이상이어야 하며, 음수면 `400` `C103`

|`size`
|`20`
|페이지 크기. 1 이상 1000 이하여야 하며, 범위를 벗어나면 `400` `C104`
|===

숫자가 아닌 값을 보내면 `400` `C106` 입니다. 응답의 페이지 정보 필드 이름은 API마다 다르며, 현재 페이지 번호는 모두 요청과 같이 0부터 시작합니다.

[cols="2,2,5,5"]
|===
|형식|목록 필드|페이지 정보 필드|사용하는 API

|Spring Page 형식
|`content`
|`number`(현재 페이지), `size`, `totalElements`, `totalPages`, `first`, `last`, `numberOfElements`, `empty`, `pageable`, `sort`
|즐겨찾기한 게시판 목록, 하루 덕담 목록, 알림 목록, 안 읽은 알림 목록, 덕질노트 목록

|`page` 형식
|`content`
|`page`(현재 페이지), `size`, `totalElements`, `totalPages`, `isLast`
|콘테스트 목록, 이벤트 목록, 내가 참여한 콘테스트·이벤트 목록, 내 수상 콘테스트 목록, 내 당첨 이벤트 목록

|`currentPage` 형식 (피드)
|`feeds`
|`currentPage`(현재 페이지), `size`, `totalElements`, `totalPages`, `hasNext`, `hasPrevious`
|게시판별 피드 목록, 내가 쓴 피드 목록, 내 수상 피드 목록

|`currentPage` 형식 (댓글)
|`comments`
|`currentPage`(현재 페이지), `pageSize`, `totalElements`, `totalPages`, `hasNext`
|피드 댓글 목록, 하루 덕담 댓글 목록

|개수 형식
|`blocks`
|`totalCount`(전체 개수), `hasNext`
|차단한 사용자 목록, 차단한 키워드 목록
|===

[[overview-error-response]]
=== 에러 응답 구조

모든 에러 응답은 다음 구조입니다.

[source,json]
----
{
  "code": "에러 코드",
  "message": "에러 메시지"
}
----

* 클라이언트 분기는 `code` 로 하세요. `message` 는 표시·로그용 문구로 바뀔 수 있습니다. 같은 성격의 에러라도 API마다 HTTP 상태가 다를 수 있습니다(예: 이미 좋아요한 피드 `LK102` 는 400, 이미 차단한 사용자 `BL301` 은 409).
* code 접두어는 도메인을 나타냅니다: `C` 공통, `AU` 인증, `MB` 회원, `EM` 이메일, `FD` 피드, `BO` 게시판, `CN` 콘테스트, `EV` 이벤트, `DM` 하루 덕담, `FN` 덕질노트, `LK` 좋아요, `NF` 알림, `PR` 취향, `RL` 칭호, `BL` 차단, `RP` 신고, `IM` 이미지, `AD` 관리자(관리자 페이지 전용). 코드 목록은 <<error-code-api>>로 조회할 수 있습니다.
* 각 API 문서의 *에러 응답* 항목 제목은 `에러 이름` · HTTP 상태 · code — 발생 조건 형식입니다(예: `FEED_NOT_FOUND` · 404 · FD001 — 존재하지 않는 피드 ID). 에러 이름은 응답 본문에 포함되지 않습니다.
* 아래 <<overview-common-errors>>는 여러 API에서 공통으로 발생하므로 각 API 문서에는 반복하지 않습니다.

[[overview-common-errors]]
=== 공통 에러

[cols="1,1,3,6"]
|===
|HTTP|code|이름|발생 조건

|400
|`C101`
|`INVALID_INPUT`

[[overview-http-status]]
=== HTTP 상태 코드

성공 여부는 2xx 전체로 판단하세요.

|===
|상태 코드|설명

|`200 OK`
|요청 성공. 생성·수정·삭제 API도 아래 두 경우를 제외하면 200과 본문을 반환합니다.

|`201 Created`
|리소스 생성 성공. <<block-member-create>>, <<block-keyword-create>>, <<report-create>>에서만 반환합니다.

|`204 No Content`
|요청 성공, 응답 본문 없음. <<member-withdraw>>에서만 반환합니다.

|`400 Bad Request`
|잘못된 요청 (입력값 오류, 도메인 규칙 위반)

|`401 Unauthorized`
|인증 실패 (`AU201` 등)

|`403 Forbidden`
|권한 없음 (다른 회원의 리소스 변경, 프로필 설정 전 `MB201` 등)

|`404 Not Found`
|리소스를 찾을 수 없음, 또는 존재하지 않는 API 경로 (`C201`)

|`405 Method Not Allowed`
|지원하지 않는 HTTP 메서드 (`C202`)

|`406 Not Acceptable`
|지원하지 않는 `Accept` (`C204`)

|`409 Conflict`
|리소스 충돌 (중복 등록, 동시 요청 충돌 `C301`, 무결성 위반 `C302`)

|`413 Payload Too Large`
|업로드 크기 초과 (`C205`)

|`415 Unsupported Media Type`
|지원하지 않는 `Content-Type` (`C203`)

|`500 Internal Server Error`
|서버 오류 (`C401`, `C402` 등)

|`503 Service Unavailable`
|외부 서비스를 사용할 수 없음. `AU402`: 소셜 로그인 제공자 오류로, 잠시 후 다시 시도하세요. `IM402`: 서버에 이미지 저장소가 설정되어 있지 않아 이미지 업로드를 처리할 수 없습니다.
|===
